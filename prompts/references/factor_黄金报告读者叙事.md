# 黄金报告读者叙事执行器

> 本执行器只控制黄金候选的读者层，不改变事实、模型、估值路由或独立审阅结论。目标是把已经闭合的研究写成一篇公司特定的投资案例，而不是把审计底稿按章节搬进正文。

## 一、先确定一条因果主线

写作前必须用一句话回答：

```text
这家公司过去靠什么赚钱 → 什么发生了变化 → 现在价值由什么支撑 →
什么事实能让价值到达普通股 → 当前价格的主要回报来自哪里。
```

正文中的公司历史、行业、同行、管理层、资产、owner cash、估值和回报都必须推进这条主线。不能把它们写成八份彼此独立的专题报告。

开篇三个自然段内应让读者看清：

1. 公司身份、规模、主要业务、关键每股或每单位数字；
2. 市场正在担心的公司特定矛盾；
3. 本报告的中心判断及其失败条件。

状态、审计、版本、模型路径和生成流程不得占据开篇叙事中心。

### 行业未来不是背景章节

正文必须形成一条 `IndustryFutureThesis`，而不是罗列宏观数据、行业趋势或同业现状：

```text
适当时域内最可能的行业变化
-> 利润池为什么迁移
-> 公司具体暴露与适应动作
-> 正常盈利、owner cash 和永久损失怎样变化
-> 当前估值或价格处理因此怎样改变
```

报告需要明确哪条行业路径当前更可能，并保留一个最强竞争解释。没有基准率时用定性
置信和范围，不填写主观概率。多个并列情景、敏感性矩阵和“以后观察某指标”只能辅助
主张，不能替代主张。若公开证据确实不能区分两条会改变投资处理的路径，仍要写出共同
下界、不为哪项成长付费，以及能够完成区分的下一事实。

## 二、章节顺序服从读者问题

完整报告可以保留既有15章外壳，但章节之间必须形成以下自然推进：

```text
公司从哪里来
→ 行业经济为何曾经支持它
→ 行业或竞争发生了什么变化
→ 同行证明哪些是行业问题、哪些是公司问题
→ 今天的业务机器和利润池是什么
→ 管理层如何影响资本归宿
→ 正常化owner cash是多少
→ 资产和索取权怎样到达普通股
→ 当前价值与未来价值怎样演进
→ 投资者现金流和主要回报
→ 永久损失、翻转事实和最终判断
```

每章开头先说明“为什么现在要回答这个问题”，再给数字。数字不得无解释突然出现；表格后必须说清它改变了什么判断。

## 三、把审计材料降到正确层级

读者正文保留足以复算投资结论的关键桥，但不承担完整底稿职责。

- 正文优先展示结论锚、总额到每股/每单位的机械换算、事实与判断边界、材料敏感性。
- 逐年长表、完整字段映射、全部情景网格和模型实现留在研究包或技术附录。
- 若一个表不能改变永久损失、价值、回报或中心论点，正文不需要它。
- `PENDING_REVIEW`、hash、bytes、schema、validator、worktree和生成状态不得进入面向投资者的叙事。
- 独立审阅发现应转化为经济解释，不能保留“退回项、关卡、阻断关闭”等制作语言。

## 四、重大数字必须先有经济身份

每个重大金额首次出现时，同时说明：

1. 它是流量还是存量；
2. 它属于合并集团、母公司、普通股还是少数股东；
3. 它是披露事实、机械换算还是研究判断；
4. 它进入现金流、经营价值、资产价值或敏感性中的哪一处。

重大资产总额应同步给每股或每单位值。资产、债务、NCI和内部往来必须在同一索取权层级闭合；经营业务价值与包含该经营业务的资产净值不得重复相加。

## 五、四种回报共同展示，只选一个主要回报

所有黄金候选至少同时展示：

```text
1. 股东现金回报
2. 书中经营经济回报：现金 + 有机经营变化 + 有效留存价值 - 衰减
3. 本公司价值路线的投资者回报：实际日期现金流XIRR或有限期限IRR
4. 估值回归贡献：有限确认回报与alpha=0回报的差额
```

必须明确标出唯一的 `PRIMARY DECISION RETURN`，不得让读者自行从多个百分比中选择。

企业类型决定主要回报：

| 企业类型 | 主要决策回报 |
|---|---|
| 护城河或复利企业 | 书中经营经济回报；市场确认只作兑现检查 |
| 综合控股或深度资产折价 | 现金回报与分部价值兑现XIRR；必须单列重估贡献 |
| 有限期限REIT/特许权 | 全生命周期现金流IRR |
| 重资产周期企业 | 跨周期正常owner earnings收益率与资本配置回报 |
| 项目型企业 | 项目资金回收、普通股owner cash和逐期XIRR |
| 清算或资产退出 | 可回收现金、时间和清算IRR |

企业同时具有两种身份时，可以展示第二回报，但仍须说明哪一个负责裁决。市场确认不能替代经营经济性；经营经济性也不能替代资产兑现所需的时间和概率。

## 六、结论必须能用自然语言复述

正式结论在离开表格后仍应成立。至少回答：

- 为什么便宜；
- 市场担忧中哪些正确、哪些可能过度；
- 不恢复时股东得到什么；
- 哪一项事实最可能翻转结论；
- 当前回报靠经营、现金、资产、重估还是清算中的哪一项过线。

若结论只能靠公式或字段名解释，读者层尚未完成。若公开信息不足，给保守区间、降低主张或保留`UNKNOWN`，不得用“保守系数”替代缺失的经济解释。

## 七、发布前的材料性检查

只做会改变内容的检查：

1. 开篇是否在三段内交代公司身份、核心矛盾和中心判断；
2. 行业未来是否选择了主路径，并传到公司适应、正常现金和永久损失；
3. 每章是否推进同一因果主线；
4. 重大金额是否有每股/每单位与索取权身份；
5. `PRIMARY DECISION RETURN`是否唯一，其他回报是否明确作用；
6. 读者能否解释价值从今天如何走到期末现金流；
7. 结论是否明确依赖经营改善、资产兑现或估值回归中的哪一项。

自动化发布还会运行 `reader_coverage.py` 的语义覆盖门。它按企业原型检查业务机制、
行业未来与公司传导、正常盈利或适用现金/NPI/FCF路线、普通股现金可达性、估值/回报/
价格身份、反方与永久损失、监控和数据边界。每项必须有读者可理解的事实→机制→影响说明；证据不足可以写
`UNKNOWN/未披露`，但必须说明它如何限制估值或动作。技术附录链接、来源清单和结构化
字段绑定只能作为锚点，不能单独关闭覆盖项。

不要为发布重复计算hash、字节数、路径身份或全仓库审计。这些不改善报告质量。
