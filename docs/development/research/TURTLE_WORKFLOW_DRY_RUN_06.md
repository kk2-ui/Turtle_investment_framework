# 研究流程干跑 06：动作后出现结果，会不会被误读为因果？

状态：`METHOD_PREPARATION_TEST / SYNTHETIC / NO_COMPANY_RESEARCH`  
目的：测试流程能否把“公司做了某事，后来结果改善”保持为行动链和待检验机制，而不自动称为管理层判断正确或因果证明。

## 1. 虚拟输入

公司 D 宣布渠道数字化和服务网点扩张。两个季度后，收入恢复、毛利率稳定；管理层称恢复来自渠道升级。同期行业补贴扩大、竞争者供给受限，且公司未披露终端 sell-out、服务时效、价格带或客户选择资料。

## 2. 旧流程干跑：暴露的问题

来源观察卡区分事实与解释，但没有标出该条材料在机制中的角色。研究者可能把“动作发生 + 结果随后发生 + 管理层归因”压缩为“渠道升级已被验证”。

根因：`REASONING`。经济影响是会把共同冲击、时序巧合或会计边界误判为渠道能力，进而高估竞争持续期、正常盈利或资本配置质量。

## 3. 流程修改

每条来源观察必须标明在机制中的角色：

- `STATE`：当时背景或约束；
- `ACTION`：可核验的资源、决策或执行；
- `OUTCOME`：后续经营/现金结果；
- `CAUSAL_ATTRIBUTION`：管理层或作者解释；
- `FORECAST`：当时完整的可结算预测。

并标明该材料对竞争机制的诊断性：`COMMON / A_SPECIFIC / B_SPECIFIC / NONDIAGNOSTIC`。行动完成只结算行动；因果归因只生成反方和下一观察。只有具有机制特异性的 outcome sequence 才能削弱或支持一条箭头。

## 4. 修改后复跑

渠道数字化为 `ACTION`，收入/毛利变化为 `OUTCOME`，管理层解释为 `CAUSAL_ATTRIBUTION`；补贴/供给约束为替代机制的 `STATE`。目前所有结果是 `COMMON` 或 `NONDIAGNOSTIC`。

正确输出：`ACTION_COMPLETE / CAUSAL_MECHANISM_UNVERIFIED`。下一步是寻找同口径客户选择、服务兑现、渠道 sell-out 或不同机制的可观察顺序，而非给渠道升级加分。

## 5. 迭代裁决

`MODIFY → RETEST_PASSED`：流程现能把动作、结果和解释分开。真实 episode 仍需检验角色标签是否帮助研究者更早发现替代机制。
