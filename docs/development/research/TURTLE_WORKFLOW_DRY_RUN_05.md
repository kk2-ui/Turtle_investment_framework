# 研究流程干跑 05：多来源/多 agent 会不会伪造独立证据？

状态：`METHOD_PREPARATION_TEST / SYNTHETIC / NO_COMPANY_RESEARCH`  
目的：测试并行阅读能否减少遗漏，却不把同一张供应商图、同一公司陈述或相同结局转述成多份独立支持。

## 1. 虚拟输入

三份外部报告和两位来源研究者都称“公司 C 在线上份额下降，竞争恶化”。复查后发现：

- 三份报告都转述同一份未物化的供应商图；
- 两位研究者阅读的是同一份公司年报，只是引用不同页；
- 唯一独立的材料是另一家供应商对行业总出货的公开摘要，但交易点不同。

若按文章数或 agent 多数投票，H-B 将看似获得五票支持。

## 2. 旧流程干跑：暴露的问题

来源观察卡虽提醒记录共同来源谱系，但没有强制 `lineage_id`；机制实验也没有把“不同文字”折叠为“同一观察”。多人协作时，主研究者仍可能将并行结果误读成证据独立性。

根因：`REASONING + ACQUISITION_MODULE`。经济影响是伪样本量会错误提高竞争机制、持续期、现金或永久损失判断的信心。

## 3. 流程修改

1. 每个来源观察卡必须标唯一 `lineage_id`、最原始可追溯来源和是否真的独立于现有观察；
2. 同一 company filing、provider release/query、访谈样本或事件链的转述必须折叠为一个 observation；
3. 只有测量生成过程、交易点和结果边界不同且可说明时，才可被并列为独立观察；不同不等于可相加；
4. 多 agent 的职责是分别做来源还原、机制构造和红队，不能投票、平均或提高概率；主研究者最终只按来源谱系和机制诊断性综合。

## 4. 修改后复跑

三份报告和两次阅读折叠为同一 `lineage_id` 的 `MECHANISM_DISCOVERY` 传感器；行业总出货因交易点不同标 `MEASUREMENT_MISMATCH`，不能与零售份额共同投票。

正确输出为 `UNRESOLVED_DEPENDENCE / UNDIFFERENTIATED`，而不是“五票支持 H-B”。并行阅读只多得到一个更清楚的资料请求：取得原始供应商 release/query 和同交易点的观察。

## 5. 迭代裁决

`MODIFY → RETEST_PASSED`：流程现在把协作效率和证据独立性分开。真实协作中仍需检查 lineage 记录是否真的能复原，而不是仅为每篇文字随意命名。
