# Runtime 资料缺口折价纠正

> campaign：`JUDGMENT_FIRST_12H_20260828`
>
> 裁决：`ACTIVE_DEFENSIVE_BIAS_REMOVED / INDEPENDENT_REVIEW_ACCEPT`
>
> 方法状态：`NOT_VALIDATED / NOT_FROZEN`

## 真实失败

Judgment-First 报告提示词已经声明“缺失本身不是固定价值毁灭”，但完整自动链仍有两个相反行为：

1. Zone J 要求字段缺失越多、折价越高，并在输入不足时默认 `15%`；
2. 统一 `run.py → extract_zone_j` 读取了不存在的内联模板字段，因此可能向模型发送空 prompt。

此外，主工作区已有多份按旧规则生成的 `data_discount.json`。即使新 prompt 修正，自动链仍会直接
复用这些文件，并把没有经济损失证据的 `15%` 乘入 `gg_discounted`。这会使报告因披露不完整而
机械偏空，正是“安全地少判断”获得奖励的运行时版本。

## 当前规则

资料缺口只有三种允许处理：降低对应主张置信度、扩大合理估值区间、取消尚未证明的溢价承保。
它没有先验方向，不能自动降低估值中枢。

非零经济折价必须绑定已观察且责任匹配的载体，例如现金不可达、关联方价值转移、持续异常占款、
资本损失或减值，并说明它如何传导到 owner cash 或永久损失。没有该载体时，
`total_discount_pct.value = 0`。这不表示资料完整，也不表示公司无风险；它只拒绝把未知方向伪装成
负方向。

## 运行时修复

- Lilu Zone J 模板现在区分信息置信度与经济折价，并要求
  `discount_basis = observed_economic_carrier_v1`；
- 统一入口复用 canonical `build_context/build_prompt`，实际发送含公司和证据上下文的非空 prompt；
- 无 Zone J 参数时，GG 点估计不再默认扣 `15%`；
- 缺少新语义标记的旧文件保留为历史审计工件，但 loader 不再应用其折价，下一次 Zone J 正常重算；
- 带标记且有经济载体的折价继续生效，不以数值大小猜测新旧语义。

没有增加全局 gate、迁移框架或批量重写。旧文件被局部忽略时报告继续运行，其他 Zone J agent 的
语义和复用方式不变。

## 验收与边界

定向验收覆盖：

- 缺失折价参数时 `gg_discounted == gg`；
- 已观察的 `8%` 经济折价仍得到 `gg × 0.92`；
- 统一入口收到非空、含公司与输入缺口上下文的 Lilu prompt；
- 真实旧格力 `15%` 文件不再进入计算，而其他 Zone J 参数仍保留；
- 旧文件成功重算后可复用，不产生额外模型调用。

独立复审为 `ACCEPT`。这证明一条已知防御性偏置已从活跃运行链移除，不证明新方法已经改善未见
公司的实际回报，也不构成 transfer、方法冻结、正式估值或投资权限。
