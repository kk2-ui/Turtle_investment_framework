# R-33：用友 2016–2017 企业互联网服务——客户数不是可结算的客户采用

状态：`RESULT_KNOWN_TEACHING / ADOPTION_METRIC_UNRESOLVED / NO_TURTLE_BACKTEST`

R-33 是 R-32 的不同中国企业边界复验，而非“用友与广联达谁更好”的比较。两者都在传统企业软件基础上推进云/服务化，但本案只在公司层披露了云客户数量、云收入与金融服务收入；它没有给出同一客户 cohort 的付费、转换、续费、流失和服务成本。

## 1. 行动和应有的机制

2016 年 8 月，用友在公司官网宣布进入以企业互联网服务为主体业务的 3.0 阶段，拟融合内部云服务、软件、金融服务与平台资源。[2016 年战略发布](https://subject.yonyou.com/zt/20160815/index.html)

合理的竞争机制不是“云服务客户多，所以云化正确”，而是：

| 机制 | 必须发生的顺序 | 可用的反方 |
|---|---|---|
| H-A：服务化形成客户价值和可持续经济性 | 可识别的传统客户/新客户采用 → 付费转换与续费/留存 → 价格、交付成本和现金能覆盖持续投入。 |  |
| H-B：规模指标混合，未形成可归因的云经济 | 客户数、云收入、金融收入或生态访问量增长，但分母混合、免费/低价获客、金融交易、成熟软件和投入共同驱动；留存/单位经济未知。 |  |

2016 年的行动原件不提供 H-A 的必要结果合同，故当时的正确研究状态是 `NO_PRIMARY`，不是选择战略方向。

## 2. 结果资料为什么仍不能裁决

2017 年年报披露：云服务收入 4.09 亿元（不含金融类云服务）、金融服务收入 8.03 亿元，用友云服务客户达到 393 万家；文件同时描述此前云服务探索与投入，并将云服务、金融服务和软件业务并列推进。[2017 年年报](https://vip.stock.finance.sina.com.cn/corp/view/vCB_AllBulletinDetail.php?id=4148016&stockid=600588)

这足以作为“业务规模与收入发生变化”的背景，但不足以结算服务化机制：

| 需要的观察 | 当前披露 | 结论 |
|---|---|---|
| 同一客户 cohort 的免费/付费、转换与流失 | 只有总云服务客户数。 | `UNKNOWN`；客户数不能当作付费采用。 |
| 同一客户的续费/合同现金 | 未找到续费、合同余额或按 cohort 的现金披露。 | `UNKNOWN`。 |
| 云服务单位价格、折扣与交付/维护成本 | 云收入与金融收入分列，但成本和服务边界未按客户/产品打通。 | `UNIT_ECONOMICS_UNKNOWN`。 |
| 客户反馈怎样改变下一次产品/资源选择 | 有战略和多产品/生态叙述，未见可核查的反馈—选择映射。 | `CAPABILITY_UNKNOWN`。 |

尤其不能把云收入与金融服务收入合并：二者的客户行为、风险、资金占用和确认逻辑不同。即使总客户数增长，也不能判断其是云产品主动使用、金融业务触达、合作伙伴/平台注册，还是一个客户持有多项服务。

## 3. 对 R-32 的边界复验

R-32 的广联达至少披露了试点范围内的转换、续费、合同、当期确认和预收，从而可将“客户开始采用”作为一条有限的早期箭头。R-33 证明，换到另一家云服务公司后，**总客户数和云收入不能代替该箭头**。

这不是近失效：两家公司业务边界、客户层级、金融业务暴露和披露口径均不同，且存在多项中介差异。因此它只能收紧适用条件，不能用于比较谁的云化能力更强，也不能形成客户采用的跨公司频率。

## 4. 训练流程的新增最小规则

在所有平台、会员、SaaS、生态与“客户数”案例中，结果合同必须逐项标出：

```text
entity and product boundary
customer identity / deduplication rule
free, trial, paid and renewed states
contract or cash event
service-cost boundary
```

缺其中任一项，数字可作为 `MARKET_REACH_BACKGROUND`，但不得作为 `ADOPTION_OBSERVED`。这项规则不要求企业披露全部数据；不能得到时只保留 `UNKNOWN`。

## 5. 根因、经济影响与接纳条件

- 根因：`DATA_COVERAGE + REASONING`。公开年报提供公司层规模，未定义客户状态、去重、付费/续费或单位服务成本。
- 经济影响：若把 393 万客户、云收入或金融收入直接读为云业务的客户价值与 owner cash，会把业务混合和投入期会计时点误判为长期经济优势；还会错误迁移到格力等渠道型企业。
- 禁止假设：客户数等于付费客户、独立客户或留存客户；收入增长等于单位价值；金融服务收入与 SaaS 收入经济性质相同；公司大战略自然就是客户反馈后的正确资源选择。
- 接纳条件：下一张服务化候选只有在 cutoff 前能冻结客户身份/状态、付费与续费、合同或现金、服务成本和反馈后的选择时才进入 `ADOPTION_OBSERVED` 或更高层；否则停在 source screen。
