# R-32：广联达 2015–2017 云化转型——客户采用可见，但不能把转换率直接叫作“能力”

状态：`RESULT_KNOWN_TEACHING / PARTIAL_OUTCOME_CONTRACT / NO_TURTLE_BACKTEST`

本卡刻意离开家电，作为中国企业“产品—服务—商业模式”能力训练的边界复验。它不评价广联达整体好坏、管理层人格、证券价格或投资价值；也不把中国软件行业的结论外推回家电。

它回答的是：**一家公司把成熟工具软件从一次性销售转向云服务时，什么观察足以证明客户开始接受，什么又仍不足以证明已形成可迁移的创新能力或 owner-cash 优势？**

## 1. 结果前的行动与经营问题

2015 年 5 月，广联达在公司官网宣布向平台化互联网公司转型，以 BIM、物联网、数据、云计算和移动互联网为主要手段；9 月的公司原件又说明，互联网服务首先围绕用户购买软件后的学习和提问场景开展，推出建筑课堂与哒哒客服。[2015 年 5 月转型公告](https://www.glodon.com/news/191.html) [2015 年 9 月服务实践](https://www.glodon.com/news/231)

这两份原件可确认的不是“云化一定成功”，而是一个有边界的经营选择：把既有专业软件关系延长到使用、学习、服务与按期交付，且为此投入新的产品与运营方式。

| 机制 | 状态 → 决策 → 首先应出现的观察 | 最怕的事实 |
|---|---|---|
| H-A：云化提高持续用户价值 | 专业用户愿意从一次性工具转成持续服务 → 转换、续费和合同积累出现 → 之后才可能形成可重复的产品/服务学习。 | 用户不转换、不续费，或只能用大量折扣/捆绑维持。 |
| H-B：形式转型而非经济能力 | 公司改变合同与确认方式，但客户价值、留存和单位服务经济未改善；总收入被成熟产品、并购/新业务或会计时间差掩盖。 | 同口径客户自愿转换、续费和可比单位贡献连续改善。 |

当时原件没有给出一个客户 cohort 的价格、服务成本、留存定义或下一轮产品选择的因果记录。因此它不能在 cutoff 就选择 H-A；其正确初始状态应是 `NO_PRIMARY`，而不是由“平台战略”强选主路径。

## 2. 结果已知后：哪些箭头被观察到

2016 年年报称，工程造价业务继续推进“云+端”；云计价产品在 11 个省份交付，在从一次性销售转为年费的省份，用户转换比例平均达到 50%。报告还给出工程造价业务收入、成本和毛利率，但该业务同时包含传统计价、算量、信息等产品，不能把分部财务归给云计价。[2016 年年报，工程造价与云计价段](https://money.finance.sina.com.cn/corp/view/vCB_AllBulletinDetail.php?id=3179913&stockid=002410)

2017 年年报进一步披露，在 6 个试点地区的计价 SaaS 模式中，用户转换率平均 80%、续费率约 85%；云转型相关合同 1.75 亿元，当年确认收入 0.45 亿元、计入预收款 1.3 亿元。文件同时明说：一次性确认的模式转为按服务期间分期确认，预收款增加会对当期和后续收入、利润产生较大影响。[2017 年年报，转型与合同披露](https://money.finance.sina.com.cn/corp/view/vCB_AllBulletinDetail.php?id=4165429&stockid=002410)

| 箭头 | 可观察结论 | 不能越过的边界 |
|---|---|---|
| 云服务客户采用 | `OBSERVED`：两期均有用户转换；2017 有续费披露。 | 2016 的 11 个省份与 2017 的 6 个试点地区并非披露出的同一 cohort，不能计算转换率趋势。 |
| 合同/现金时点 | `OBSERVED`：2017 的合同、当期确认与预收被明确分开。 | 预收款不是单位经济、自由现金或长期价值；未披露获客、交付、维护与续费服务成本。 |
| 分部经营表现 | `BACKGROUND_ONLY`：工程造价收入仍增长，毛利率有口径。 | 该分部含多种产品/传统业务，且确认方法正在改变，不能归因给云计价。 |
| 公司经营现金 | `NOT_DIAGNOSTIC`：2016 合并 OCF 上升，但公司整体业务和营运资本共同变化。 | 不得叫作云化 owner cash 或资本回报。 |

## 3. 对“创新能力”的正确结算

本案比 R-26/R-29 更接近可训练的客户采用：转换、续费、合同与递延确认都在官方结果资料中出现。因此它能训练 agent 不把研发投入、专利或发布会替代为真实客户行为。

但它仍不足以裁决 `CAPABILITY_OBSERVED`：

1. 2015 年原件说明用户场景与服务选择，却没有把某次可量化反馈明确连接到后来的产品/商业模式修改；
2. 2016 与 2017 的转换口径、地区集合与 customer cohort 没有冻结为同一分母；80% 不能机械地优于 50%；
3. 续费约 85% 没有说明价格、折扣、客户留存定义、服务成本、流失客户或在服务期后的现金回收；
4. 没有第二条预先独立的“反馈 → 下一次选择 → 采用/经济”链，因而不能把一次云化路径叫作可迁移的组织能力；
5. 采用服务期确认本身改变收入、预收与利润时点，所有会计结果都须与客户价值和单位服务成本分开读。

本卡的正确复盘为：`PRODUCT_AND_SERVICE_ADOPTION_OBSERVED / CAPABILITY_UNKNOWN / OWNER_CASH_UNKNOWN`。这不是失败；它精确地把“客户真的开始用”与“公司已建立持续学习、盈利和现金能力”分开。

## 4. 对训练飞轮的改变

创新/平台类候选现在必须在进入深读前冻结三套不可替代的观察：

```text
采用：同一 customer cohort 的转换、活跃、续费、复购或停止
经济：同一产品/服务的价格、折扣、交付/维护成本与合同现金
学习：反馈发生后，管理层扩大、修正、转向或停止的下一次具体资源选择
```

其中只有采用可见，叫 `ADOPTION_OBSERVED`；采用与经济同时可见，才可叫 `PRODUCT_ECONOMICS_OBSERVED`；三者再加一条不同产品/客户段的冻结复验，才允许使用 `CAPABILITY_OBSERVED`。这与家电产品、工业项目和软件服务共用，具体指标随行业变而不改逻辑。

## 5. 根因、经济影响和下一次准入

- 根因：`DATA_COVERAGE + ACQUISITION_MODULE + REASONING`。当前公开披露非常适合看转换、续费和会计时点，却不提供相同 cohort 的价格/成本/现金，亦未把客户反馈与下一次资源选择建立可核查链接。
- 经济影响：若把 80% 转换、85% 续费或预收增长直接升级为能力与 owner cash，会高估长期经济质量，低估服务交付、收入递延、价格让利和竞争模仿的风险；若只因收入确认变化而否定客户采用，也会错过真实的早期机制信号。
- 禁止假设：用户转换等于自愿且有价值的留存；预收等于自由现金；总 OCF、研发投入、专利或总分部毛利等于云化单位经济；两期不同试点的百分比天然可比。
- 下一次接纳条件：选取另一中国企业或另一广联达**预先独立**产品/客户段，行动前就写明同 cohort 的采用定义、价格/成本/合同现金、反馈触发的第二次选择和 H-A/H-B 的不同顺序。若不能在 cutoff 前拿到这些合同，停在 `ADOPTION_SCREEN`，不再用报告篇数补洞。
