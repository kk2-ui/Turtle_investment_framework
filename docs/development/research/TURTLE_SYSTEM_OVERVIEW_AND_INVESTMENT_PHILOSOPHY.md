# Turtle 系统总览与投资理念

> 文件身份：`CURRENT / ARCHITECTURE_ORIENTATION`
>
> 更新：2026-08-25
>
> 本文是 Turtle 的架构总览和共同语言，面向投资者、研究 Agent 和后续实现者。它解释系统为什么这样分层、各层解决什么问题，以及训练结果如何服务企业判断和买点判断。本文不是动态项目状态、具体 schema 或执行路线的替代品。

当前状态以 `docs/CURRENT_DOCUMENTS.md`、`GOALS.md` 和适用的路线图为准；具体对象的权限以代码和 schema 为准。

## 1. Turtle 要解决什么问题

Turtle 不是“自动选股器”，也不是“输入财务数据后输出目标价”的计算器。

它要帮助投资者完成一条可复核的判断链：

```text
企业是什么
  -> 靠什么赚钱
  -> 竞争优势能否持续
  -> 正常利润是多少
  -> 利润能否转成普通股股东可获得的现金
  -> 什么会造成永久性损失
  -> 当前价格隐含了什么预期
  -> 安全边际是否足够
  -> 是否值得买、持有或继续研究
```

因此，系统的中心目标不是增加报告数量、预测股票涨跌或生成更复杂的评分，而是提高 Agent 对企业经济事实的识别、传导和决策辅助能力。

## 2. 投资者真正需要的五个答案

一份有用的研究最终应当回答：

1. **赚钱机制**：企业向谁提供什么价值，收入、成本和资本占用如何形成？
2. **持续性**：竞争、客户、供给、管理层和资本配置能否让这种赚钱机制持续？
3. **现金兑现**：利润、经营现金和账面资产中，哪些能真正到达普通股股东？
4. **永久损失**：什么变化会让企业价值永久下降，而不只是短期业绩波动？
5. **价格关系**：当前价格要求企业实现什么，预期回报和安全边际是否值得承担风险？

这五个问题对应 Turtle 的研究、训练、估值和报告边界。任何单一利润率、估值倍数或历史涨跌都不能独立替代它们。

## 3. 总体架构

```text
                    ┌──────────────────────────┐
                    │  当前价格与投资决策层     │
                    │  估值、预期差、BuyBand    │
                    └────────────┬─────────────┘
                                 │ 只读企业判断，不能反写
                    ┌────────────▼─────────────┐
                    │  企业判断层：CJO          │
                    │  经营机制、现金、风险、反方 │
                    └────────────┬─────────────┘
                                 │
          ┌──────────────────────▼──────────────────────┐
          │ Decision Contract + Measurement Contract       │
          │ 研究目的、cutoff、时域、权限、结果如何结算     │
          └──────────────────────┬──────────────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │ 官方证据与 PIT 层         │
                    │ 来源、页码、责任边界、时点 │
                    └────────────┬─────────────┘
                                 │
                    ┌────────────▼─────────────┐
                    │ 训练与反馈层              │
                    │ 历史、Teaching、Forecast  │
                    │ Comparative、Learning     │
                    └──────────────────────────┘
```

这不是一个允许各层自由互相覆盖的流水线。每层有自己的责任：

- 证据层回答“当时知道什么”；
- 合同层回答“这次研究要判断什么、未来如何验证”；
- 企业判断层回答“企业经营是否值得承保”；
- 估值层回答“在当前价格下是否值得承担风险”；
- 训练层回答“系统是否真的从过去的判断中变得更好”；
- 报告层只是把已冻结的内容编译成投资者可读的完整研究。

## 4. 证据层：先建立可审计事实

Turtle 的重大事实必须回到官方文件、审计财报或交易所公告，并记录：

- 公司和责任边界；
- 信息截止日；
- 来源包和文件版本；
- 页码或字段引用；
- 数据的期间、单位和合并口径；
- 可使用、不可使用和未知的内容。

历史研究必须遵守 PIT：不能用后来公告、今天的公司网页、结果信息或事后同行判断去改写当时的研究条件。

`UNKNOWN` 不是系统失败，而是对投资者有价值的结果。它表示当前证据不足以支撑一个不会误导决策的判断。

## 5. 两份关键合同

### 5.1 Decision Contract

Decision Contract 在研究开始前冻结：

- 这次研究服务什么决策；
- 截止日和持有时域；
- 需要保护的永久损失边界；
- 允许产生哪些输出；
- 哪些证据会改变判断；
- 研究预算和比较基线。

没有它，系统无法判断一项新增研究是否真的改善了投资决策。

### 5.2 Measurement Contract

Measurement Contract 定义未来的官方披露如何映射到每一个 Forecast cell 或判断项。它必须明确：

- 指标定义、单位、分子和分母；
- 公司责任边界和合并口径；
- 结算窗口和会计期间；
- 允许的官方字段和页码；
- 字段到标签的确定性映射；
- 缺失、冲突、删失和无法识别时的处理。

“结果期有公开年报”不等于“结果可结算”。如果年报有经营现金流，却不能区分维护性资本开支与增长性资本开支，就不能伪造 owner-cash 标签。

Measurement Contract 必须独立提供给结果 custodian。custodian 不应看到预测概率、排序、判断理由或行动内容，否则结算可能受到预测内容污染。

当前水泥 2018 Forecast 暴露的正是这一层缺口：资料存在，但部分结果无法无歧义映射到冻结定义，因此应保留 `EVIDENCE_INELIGIBLE` 或 `MEASUREMENT_MISMATCH`，而不是强行标记 `OBSERVED`。

## 6. 企业判断层：CJO 是核心产品

CJO（Company Judgment Object）是对企业经营状态的冻结判断，不是报告正文，也不是交易指令。

它应当把以下链条连起来：

```text
经营驱动
  -> 正常化利润
  -> 资本支出与营运资本需求
  -> owner cash / 普通股现金可达性
  -> 企业价值与永久损失风险
```

CJO 必须保留：

- 关键经营驱动；
- 机制和责任边界；
- 最强反方；
- 证据缺口；
- 可结算判断；
- 未来监测条件；
- `UNKNOWN` 和保守处理。

CJO 的作用是防止当前价格、估值模型或报告写作反过来塑造企业事实。

## 7. 训练层的分工

训练对象不是一个“大样本池”，而是按主张和证据能力分层。

| 训练轨道 | 投资意义 | 能否直接证明选股方法有效 |
|---|---|---|
| Industry History | 认识行业发展、退出、失败和生命周期 | 不能 |
| Teaching / Boundary | 学习机制、测量边界和常见误判 | 不能 |
| Forecast | 预测企业状态，检验校准、覆盖和不确定性 | 不能直接证明因果选股 |
| Comparative | 在机制定义的竞争范围内比较行动与反事实 | 只有满足严格结算后才可能 |
| Learning | 把已结算错误变成下一公司可审计的研究变化 | 必须证明迁移 |
| Prospective Shadow | 检验部署后的未来时钟和污染控制 | 不是历史训练成绩 |

### Industry History 与 Lifecycle

消失、被收购、退市、失败或退出业务的公司仍有训练价值。它们帮助系统认识：

- 哪些优势最终会消失；
- 哪些经营改善只是短期现象；
- 哪些资本配置会造成永久损失；
- 资料中断和企业退出应如何处理。

### Forecast

Forecast 主要预测企业状态，而不是股票涨跌，通常包括：

- 正常利润；
- ROIC 或经营利润率；
- 现金转换和资本负担；
- 杠杆和财务韧性；
- 竞争位置；
- 永久损失风险。

Forecast 的结果只能修改与其识别强度相称的校准、覆盖率、状态定义或不确定性政策。它不能自动成为 CJO、估值或买点。

### Comparative

Comparative 要求企业有明确的已实施行动、可定义的竞争经济体、固定反事实和独立的经营与现金结果。竞争范围由机制定义，不由“同一省份”这一单一字段决定。

水泥 H2 当前没有合格的公司级行动证据，所以方向性 Comparative 样本仍为零。这不影响水泥作为行业史、Teaching 或 Forecast 训练对象。

### Learning

真正的 learning 必须是：

```text
独立结算
  -> 识别失败属于数据、取证、推理、模型或写作
  -> 改变下一轮字段、取证顺序、反方或停止规则
  -> 应用于未见公司或新 cutoff
  -> 独立审阅确认改变真实发生
```

只有复盘文字，没有下一对象的冻结字段变化，不能称为训练能力提升。

## 8. 估值与投资 Overlay

企业判断完成后，才进入 Investment Overlay：

```text
冻结 CJO
  -> 资产价值 / 盈利能力价值 / owner-cash 价值
  -> 当前价格与市场隐含预期
  -> 未来现金流与永久损失情景
  -> 回报要求和安全边际
  -> BuyBand / Watch / Research / No primary
```

不同模型回答不同问题，不能机械平均成一个 `V_final`：

- NAV 不是盈利能力价值；
- 盈利能力价值不是现金可达性；
- 账面现金不是自动可分配现金；
- 低估值不是自动的安全边际；
- 历史市场回报不是企业经营结果。

价格只能作为估值和决策输入，不能成为历史企业判断的证据，也不能为没有方向性证据的公司制造中心路径。

## 9. 黄金报告的作用

黄金报告不是训练系统本身，而是训练和研究结果的产品出口。

它必须把以下内容传递完整：

```text
关键经营驱动
  -> 正常利润
  -> owner cash / FCFF / 普通股现金
  -> 价值身份
  -> 当前价格
  -> 主要回报
  -> 买入、观察或否决条件
```

报告可以读取三类受控视图：

- `RESEARCH_AGENDA`：哪些问题值得继续研究；
- `JUDGMENT_SYNTHESIS`：冻结后的企业判断；
- `INVESTMENT_ENRICHMENT`：估值、预期差和投资决策补充。

报告生成器不能自行补事实、改模型、绕过未知或把内部状态码写成投资结论。它是只读编译器，不是第二个研究真源。

## 10. 结果状态如何理解

投资者可以这样理解常见状态：

- `UNKNOWN`：证据不足，暂时不能判断；
- `NO_PRIMARY`：没有足够方向性证据形成中心路径；
- `MIXED`：不同经济层次的结果方向不一致；
- `EVIDENCE_INELIGIBLE`：资料或口径不足，不能评分；
- `MEASUREMENT_MISMATCH`：资料存在，但无法映射到冻结定义；
- `CANDIDATE_ONLY`：离线验证通过，但还没有生产权限；
- `REPORT_USE_NOT_RELEASED`：不能进入正式黄金报告结论。

这些状态不是为了让系统显得谨慎，而是为了避免把不确定性伪装成确定性，从而改变投资结论。

## 11. 当前架构成熟度

当前最准确的判断是：

```text
证据与 PIT 控制：较成熟
Decision Contract 和权限边界：已形成
企业判断与训练对象分层：已形成
Forecast 离线入口：已实现
Measurement Contract：正在补齐
真实结果结算：尚未形成有效样本
跨公司学习迁移：尚未证明
方法留出：尚未释放
Canonical CJO -> BuyBand：尚未开放生产权限
训练 -> 黄金报告：已接线，但尚未授权为能力改进证据
```

因此，Turtle 目前已经不是简单的报告生成器，但也还不能宣称是经过验证的自动投资系统。它处于“研究控制面已成形，真实学习和决策增量仍需证明”的阶段。

## 12. 后续 Agent 的固定阅读顺序

新 Agent 应按以下顺序理解系统：

1. `AGENTS.md`：工程、证据和审阅规则；
2. `docs/CURRENT_DOCUMENTS.md`：当前真源和文档权限；
3. `GOALS.md`：当前状态和执行出口；
4. 本文：理解中心目标、分层和投资语言；
5. `TURTLE_TRAINING_SYSTEM_TOP_LEVEL_ARCHITECTURE.md`：训练和学习控制细节；
6. `TURTLE_HISTORICAL_TRAINING_SYSTEM_REDESIGN.md`：历史对象、生命周期和准入重构；
7. `TURTLE_AGENT_ENTERPRISE_JUDGMENT_ROADMAP.md`：企业判断路线和阶段门；
8. 具体 schema、validator、测试和当前审阅工件。

遇到文档之间的状态冲突时，回到 `docs/CURRENT_DOCUMENTS.md` 和 `GOALS.md`，不要用本文覆盖动态状态。

## 13. Turtle 与年糕的边界

Turtle 负责研究事实、企业判断、估值参考、反方、证伪条件和 ResearchBundle。

年糕负责在独立边界内读取研究结果、结合当前行情和用户确认处理持仓、计划和成交。Turtle 不拥有真实账户、持仓、计划或自动交易权限。

这条边界保证：

- 研究不会被账户动作反向污染；
- 当前价格变化不会改写冻结企业事实；
- 估值参考不会自动变成用户已确认的投资动作。

## 14. 一句话总结

> Turtle 先像承保人一样判断企业，再像估值师一样判断价值，最后才像投资者一样比较价格；训练的目的，是让这条判断链在未见公司和未来时点上变得更可靠，而不是让系统更快地产生一个看似确定的买点。
