# Phase 03：行业原型与估值路由

> 状态：COMPLETE ｜ 优先级：P0 ｜ 依赖：Phase 01、02 ｜ 最后更新：2026-08-02

## 1. 要解决的问题

通用章节和多公式平均无法保证模型适用。项目已有130家公司估值资料及Graham到Buffett案例，但尚未转成可执行的公司原型、证据要求和模型路由。

## 2. 目标与非目标

- 建立版本化原型注册表：商业机制、关键变量、红旗、适用/禁用模型。
- 允许一家公司匹配主原型和次原型，并显式处理冲突。
- 估值路由必须说明为何使用、为何不用，以及模型脆弱点。
- 不把历史案例机械复制到当前公司，不用模型数量制造“交叉验证”。

## 3. 核心接口

- `company_archetype.json`：原型、匹配证据、反证、置信度、所需事实。
- `valuation_route.json`：适用模型、禁用模型、参数口径、敏感变量、终值依赖和决策用途。
- 原型注册表和模型适用性规则必须版本化；报告保存所用版本。

### 3.1 输入真源

- `analysis_contract.json`：行业分类、周期性、有效历史窗口和资产类型。
- `report_context.json`：Phase 01的VERIFIED事实、冲突与缺口。
- `compute_bundle.json`：现金流口径、GG、资本结构、分红和估值敏感性。
- `industry_context.json`：同行分布，只用于行业位置和异常识别，不把同行倍数当内在价值。
- Phase 02 `decisive_question_plan.json`：说明哪些模型差异会改变决策。

旧报告自由文本、案例工作簿中的公司参数和文件名关键词不得成为当前公司事实。

### 3.2 注册表与输出契约

- `config/archetype_valuation_registry.v1.json`：原型身份、匹配规则、反证、关键事实、允许/禁用模型、模型口径和脆弱性规则。
- `config/valuation_reference_index.json`：130家公司资料目录的文件级索引、哈希、标签和用途限制；仅证明机制来源可追溯。
- `company_archetype.json`：主/次原型、逐条匹配证据、反证、冲突、置信度、缺失事实及注册表版本。
- `valuation_route.json`：主模型、佐证模型、压力模型、禁用模型、股权/企业价值口径、敏感变量、终值规则和用途。

新unified run必须在决定性问题生成和正文写作前固化原型及路由。旧目录没有`valuation_route_policy.json`时保持`SKIP`。

### 3.3 路由原则

1. 模型角色只能是`primary/corroborative/stress/rejected`，数量不能替代独立性。
2. 多模型不得做无依据加权平均；必须写明哪个模型负责决策、哪个只验证边界。
3. FCFF必须对应企业价值和WACC，FCFE/DDM必须对应股权价值和股权成本。
4. 周期公司必须先正常化；金融机构不得把一般企业FCFF DCF当主模型。
5. DDM只有在分配政策与可分配现金匹配时可作为主模型。
6. `r-g`、终值占比和组合压力必须进入路由，不留给正文临场发挥。

## 4. 实施工作包

1. 盘点130家公司模型及书中案例，区分可迁移机制与个案结论。
2. 先建立少量高覆盖原型：成熟消费/制造、物业服务、轻资产媒体、金融、重资产周期等。
3. 为每个原型定义证据清单、竞争解释、资本配置问题和估值路由。
4. 校验股权/企业价值、名义/实际、税前/税后、期间和终值口径。
5. 加入脆弱性测试：小幅参数变化、终值占比和结论翻转。
6. 以真实样本校准，未参与设计的公司作为控制样本。

## 5. 质量门

- `INVALID`：模型与公司现金流归属不匹配；关键口径混用；`r <= g` 或极端终值未警示；模型输出被误当成唯一目标价。
- `INCOMPLETE`：无法识别原型或缺少模型所需关键事实。
- `WARN`：可用模型高度脆弱，只允许范围结论和较低动作置信度。

## 6. 完成标准

- [x] 每个模型有适用、禁用和脆弱性规则。
- [x] 多模型结果不做无依据加权平均。

## 7. 剩余限制

本阶段输出结构化路由；关键报告章节的单向生成由Phase 04完成。

行业分类仍受上游行业标签粒度限制，例如“广告包装”同时覆盖媒体与包装制造。当前系统会保存匹配证据、反证和置信度；无法达到最低置信度或缺少关键输入时为`INCOMPLETE`，不会让模型自由猜测。更细的业务分部分类在Phase 05案例库积累后继续校准。

## 8. 阶段完成摘要

已建立9类公司原型和11种模型机制的版本化注册表，覆盖物业服务、成熟消费制造、轻资产媒体平台、金融、重资产周期、公用事业、房地产开发/资产持有、收入前生物科技和一般经营企业。每个原型均定义行业匹配、反证、研究要求、主模型、佐证模型、压力模型和禁用模型。

`company_archetype.json`和`valuation_route.json`在新unified run的Phase 3.85自动生成，早于Phase 02决定性问题和正文写作。估值账本必须引用`route_model_id`，并服从模型角色、现金流范围、股权/企业价值范围、折现率类型和独立假设组；所有路由禁用模型必须显式入账说明拒绝理由。completion和V3成绩单将估值路由作为独立不可补偿硬门。旧目录没有policy继续`SKIP`。
