# Phase 10：历史时点研究回测

> 状态：PILOT_PREREGISTERED ｜ 优先级：P1 ｜ 依赖：Phase 01–09 ｜ 建立日期：2026-08-03

> 2026-08-16：完成第一阶段可执行边界。实验、冻结案例、完整 Markdown 报告、独立逐 claim 审阅、模型记忆可信度和结算对象均有 schema 与校验器；当前九份候选因缺少可验证历史报告 vintage，合格案例数诚实登记为 0。600340 来源仓、真实冻结报告、走步结算和年糕投影尚未启动。

实现入口：`scripts/historical_backtest.py`；试点登记：`config/historical_backtest_pilot.v1.json`；对象约束：`schemas/historical_backtest_*.schema.json`。本阶段不修改个股模型、不产生回测收益结论、不解锁 G3。

## 1. 目标

允许用户选择公司和历史模拟时点，例如：

```text
公司：某上市公司
模拟决策日：2021-08-31
信息截止：2021-08-31 18:00（交易所时区）
评价期限：1年、3年、5年
```

系统使用当前Turtle统一分析框架，但只能读取截止时点已经公开的信息，生成一份仿佛身处当时的完整报告。随后按真实披露顺序走步结算问题、预测、阈值和动作，并用未来经营结果与投资结果评价报告质量。

该功能评价的是“当前框架面对历史信息集会作出什么判断”，不是伪造一份2021年真实存在的报告，也不能替代真正前瞻样本。

## 2. 与现有功能的区别

- 年糕当前`run_backtest`比较买入价、估值锚和当前价，属于结果摘要，不控制历史信息集。
- Phase 06 `historical_disclosure_replay`验证事件、事实差异和阈值管线，并明确`calibration_eligible=false`。
- Phase 10必须先生成严格point-in-time报告，再按时间顺序逐期揭示未来信息并结算，不能先看到结果后补写预测。

## 3. 实验预注册

任何回测运行前先生成不可修改的`backtest_experiment.json`，至少冻结：

- `experiment_id`、公司身份、上市市场；
- `simulation_cutoff`及交易所时区；
- 允许的最晚披露时间和模拟交易执行时间；
- 评价期限、基准指数、计价币种；
- 分红、拆并股、配股、退市和停牌处理规则；
- 当前框架、代码、模型、提示词、政策和数据集版本指纹；
- 公司是事先选择还是事后挑选；
- 评价指标及失败条件；
- 是否允许Web、允许哪些历史档案源；
- 模型记忆泄漏等级。

预注册之后才能读取结局数据。实验定义变更必须新建`experiment_id`，禁止覆盖旧结果。

## 4. 历史信息围栏

### 4.1 双时间身份

每项数据同时保存：

- `data_as_of`：数据描述的经济期间；
- `published_at`：市场何时能够看到；
- `ingested_at`：系统何时取得；
- `revision_published_at`：后来重述何时公开；
- `source_version`和可定位的版本身份。冻结报告与模型控制证据只额外保留 SHA-256，用于发现内容变更并强制重审；它不作为来源质量分数或研究结论。

准入条件以`published_at <= simulation_cutoff`为主，不能因为财务年度属于2020年就自动认为2021年初已经可见。后来重述的数据只有在重述披露后才能使用。

### 4.2 数据源限制

- 年报、中报、公告必须使用当时已发布的原始版本。
- 财务数据库若只保留“当前修订值”，不得作为历史事实真源。
- 宏观、行业和利率数据也必须使用当时发布版本；后修订统计不得倒灌。
- 市场价格只能使用cutoff当日及以前的原始价格；估值不得看到未来价格区间。
- 当前网页搜索默认禁止，因为搜索排序、摘要和页面内容可能包含未来信息；只有可验证发布时间和历史内容快照的来源才能进入。
- 其他公司案例和基准率同样受cutoff限制，禁止把后来结果已知的案例当成当时先验。

### 4.3 运行隔离

回测运行使用独立沙箱目录，只挂载准入后的历史证据包、当时市场数据和框架文件。禁止读取：

- 该公司cutoff后的Turtle输出；
- 当前年糕数据库中的未来行情、估值和备注；
- 后续公告、后续报告及其文件名摘要；
- 包含未来结果的案例库字段；
- 同一实验已生成的结算和评分文件。

工具层必须按来源身份拒绝未来文件，不能只靠提示词要求模型“不要看”。每次读工具调用记录准入裁决和cutoff。

`scripts/phase10_pit_runner.py` 现已提供 source-package allowlist、只读 `source_id`/framework 读取和 ALLOW/DENY read audit；production origin 会回放 attestation、source manifest、case source identity、cutoff、package root 和已读取来源。它不增加来源内容 hash。真实 600340 catalog 仍没有完整公告枚举或本地 package path，故 runner 保持 `INCOMPLETE`。

普通 `turtle_agent` 的既有读工具尚未注入该 boundary，仍可能按普通 `output_dir` 扫描文件；它们不得用于 PIT。PIT framework root 固定为仓库内受控静态目录，调用者不得以普通 output、结算或公司资料目录替换它；attestation 同时记录 root 与 `REPOSITORY_STATIC` provenance。`--pit-writer` 是独立 context：只注册 `pit_list_sources`、`pit_read_source`、`pit_read_framework` 和无路径参数的 `pit_write_report`，不加载 contract、旧输出、tracking、数据库、Web 或价格。writer 只能引用同一运行中实际 ALLOW 的 source_id，最终 `pit_runner_attestation.json` 写入真实 read audit 和 writer outcome。

启用 `--pit-source-manifest` 和 `--pit-package-root` 时，必须在 `--pit-preflight` 与 `--pit-writer` 中二选一，并使用新/空 output、`--validation-only`。preflight 只验证来源包；writer 生成一份受限 Markdown 草案，明确禁止收益、买点、选股、仓位和事后结论。该草案尚未接入 Phase 08 acceptance/V3、完整 frozen claim/calibration ledger 或独立 reviewer；因此 PIT attestation 仍只是 `VERIFIED_ARTIFACT_AND_DECLARED_PROCESS`，production validator 明确保持 `INCOMPLETE`，case 不得标为生产 `ELIGIBLE` 或严格回测。

## 5. 大模型参数记忆限制

2026年的模型可能在训练中见过该公司2021年以后的事件。即使文件围栏完全正确，也不能保证模型内部没有后见信息。因此回测必须分别报告：

- `DATA_LEAKAGE_CONTROL`: 数据和工具是否严格无未来信息；
- `MODEL_MEMORY_CONTROL`: `CONTROLLED / MITIGATED / UNCONTROLLED`；
- `BACKTEST_CREDIBILITY`: `STRICT / QUALIFIED / EXPLORATORY`。

可采用的缓解措施包括公司别名、移除证券代码和未来提示性元数据、限制自由Web、让关键问题和数值推导优先走确定性模块、独立检查文本是否提到cutoff后事件。但公司业务和历史数字可能仍足以被识别，因此匿名化不能被宣称为完全消除记忆泄漏。

模型记忆为`UNCONTROLLED`时，`BACKTEST_CREDIBILITY`必须为`EXPLORATORY`，并且只能作工程/推理诊断；不得称为严格盲测、校准结论或与真实前瞻Brier样本混合。`MITIGATED`必须有缓解证据且至多为`QUALIFIED`；未来 `STRICT` 只允许部署级 attestation 支持的`CONTROLLED` case，当前 validator 未开放该路径。模型记忆受控只是进入独立校准审查的必要条件，仍不能取代跨发行人、跨 cutoff 和 holdout 设计。

## 6. 两阶段执行

### 6.1 冻结报告阶段

统一管线在历史信息围栏内生成，并以 `variant_id -> freeze_id -> review_id` 绑定不可变生命周期；任意测试 Markdown 只走 `TEST_FIXTURE` 回归分支，不能成为生产历史报告：

- 官方证据与未解决缺口；
- 决定性问题及竞争解释；
- 估值模型和输入；
- 概率、阈值和预测到期日；
- 估值区间、动作、仓位及买卖条件；
- 完整V3质量门结果；
- 不可变回测发布快照。

报告未冻结前禁止打开未来资料。若报告因质量门失败，失败本身就是结果，不能人工修到通过后只保留最好版本。

### 6.2 走步结算阶段

冻结后按真实发布时间顺序逐步开放新披露，而不是一次性看到2026年结果。每个节点复用Phase 09：

1. 同期可比和口径检查；
2. 决定性问题逐题结算；
3. 经营变化—干扰因素桥；
4. 阈值、概率及趋势状态更新；
5. 估值和动作是否应修订；
6. 修订是否及时。

这样既评价2021年初始报告，也评价框架在2022、2023等新证据出现时能否及时改变判断。

## 7. 投资结果引擎

投资结果必须使用可执行时点和总股东回报：

- 默认从报告冻结后的下一交易日开盘或预注册价格规则开始，避免使用生成报告时尚不可交易的价格；
- 收益包含现金股息、拆并股、配股、要约、退市和并购对价；
- 同时输出本币收益和统一计价币种收益，汇率规则预注册；
- 与同市场宽基、行业基准及无风险资产比较；
- 输出1年、3年、5年或到退市日的总回报、年化回报、超额回报、最大回撤、下行捕获和达到估值锚所需时间；
- 若报告建议不买，评价避免的损失和机会成本，而不是强行假设持仓；
- 若有仓位建议，组合回报按当时建议仓位计算，剩余资金按预注册现金基准计息；
- 禁止只用当前股价减买入价，也禁止忽略分红和已退市公司。

## 8. 质量评价分层

结果不得压成一个可被抵消的总分，至少分开显示：

### 8.1 当时报告质量

- 数据真实性、时效性和口径一致性；
- 主张—证据支持关系；
- 决定性问题和竞争解释质量；
- 模型适用性和敏感性；
- 估值、动作和仓位一致性；
- 未知是否被诚实保留。

### 8.2 预测与论点质量

- 预测结算和概率事件评分（概率/Brier 需要另行注册事件定义；当前 v1 仅支持数值阈值，不产生 Brier）；
- 置信区间覆盖；
- 哪些决定性问题真正具有区分力；
- 阈值命中、误报、漏报和提前量；
- 论点翻转是否及时；
- 模糊、不可证伪预测不因“沾边”得分。

### 8.3 决策质量

- 预期回报与实际总回报偏差；
- 相对基准超额回报；
- 下行情景覆盖与永久损失；
- 买入、等待、减仓和退出动作是否与当时证据一致；
- 好过程但坏运气与坏过程但好运气分别标记。

### 8.4 框架诊断

- 数据泄漏率和未来信息拒绝次数；
- 参数冲突和口径冲突；
- 决定性问题覆盖率；
- 哪些行业原型、模型和阈值系统性失效；
- 运行成本和人工介入次数。

## 9. 防止选择偏差

单公司回测适合做工程验收和案例复盘，但不能证明框架有效。正式评价至少需要：

- 在运行前冻结公司名单和历史起点；
- 包含当时上市但后来退市、被收购或表现差的公司；
- 不因当前知道“它后来很成功”才只选赢家；
- 使用多个市场周期和多个起点进行walk-forward；
- 调参样本、验证样本和最终控制样本隔离；
- 同一规则在失败样本上也保留结果，禁止只展示最好报告。

用户临时指定的公司应标记为`USER_SELECTED_CASE`，展示价值很高，但不进入无偏总体胜率声明。

## 10. 年糕Web展示

年糕新增独立“历史研究回测”区域，与真实前瞻监控严格分栏。至少展示：

1. 实验卡：公司、cutoff、可见资料范围、框架版本、泄漏控制等级；
2. 当时报告：估值、动作、决定性问题和质量门；
3. 走步时间轴：后来每份披露如何回答旧问题及何时改变判断；
4. 预测结算：数值阈值与实际观察；概率事件及 Brier 只有在独立事件 schema、分母和结算规则注册后才可加入，当前 v1 不输出；
5. 投资路径：策略总回报、基准、股息、回撤和动作节点；
6. 归因面板：经营判断正确性、估值偏差、市场估值变化、运气和未解释项；
7. 失败审计：任何未来信息拒绝、不可比数据和模型记忆风险。

年糕只读取已冻结实验与结算账本，不允许从UI修改历史报告或筛掉失败实验。

## 11. 机器状态

- `INVALID`: 发现未来数据、历史报告被覆盖、结算先于报告冻结、不可执行价格、幸存者样本被冒充总体结果。
- `INCOMPLETE`: 披露时间无法验证、历史版本文件缺失、公司行动或分红数据不完整、基准缺失。
- `QUALIFIED`: 数据围栏通过但模型记忆无法完全控制；允许研究诊断，不称严格盲测。
- `REVIEWABLE`: 单公司走步实验完整，可人工审阅。
- `BACKTEST_READY`: 预注册样本篮子、泄漏审计、走步结算和结果引擎均通过。

## 12. 实施顺序

1. 实验预注册schema、独立目录和不可变状态机。
2. 来源双时间身份、历史文件版本库和cutoff准入网关。
3. 当前统一管线的历史信息沙箱与读工具审计。
4. 报告冻结及未来信息泄漏对抗测试。
5. Phase 09走步结算接入。
6. 总股东回报、公司行动和基准结果引擎。
7. 年糕只读投影、API和Web回测页面。
8. 单公司工程验收，再进行预注册多公司、多起点控制样本。

## 13. 验收标准

- [ ] 以2021年cutoff运行时，所有可读来源的`published_at`不晚于cutoff，未来文件即使存在于工作区也无法通过工具读取。
- [ ] 当前修订数据库值不能替代当时披露版本，后来重述只在其披露节点进入。
- [ ] 报告冻结前无法读取任何结算和未来行情文件。
- [ ] 未来披露按真实发布时间逐个开放并完成Phase 09问题结算。
- [ ] 收益包含股息、公司行动、退市和基准，使用预注册可执行价格。
- [ ] 报告质量、预测质量和投资结果分栏，收益不能抵消事实或模型错误。
- [ ] 模型记忆无法控制时醒目标记`QUALIFIED/EXPLORATORY`。
- [ ] 单公司失败结果不可删除，多公司评价包含退市及失败样本。
- [ ] 年糕Web区分历史回测、历史工程回放和真实前瞻监控。
