# Phase 09：纵向论点跟踪与年糕可视化

> 状态：PLANNED ｜ 优先级：P1 ｜ 依赖：Phase 01、02、04、06、08 ｜ 建立日期：2026-08-03

## 1. 要解决的问题

Phase 06已经能冻结发布快照、摄取新披露、记录事实差异、结算阈值并输出校准面板，但还不能稳定回答研究者真正关心的问题：

1. 旧报告提出的决定性问题，在新中报或年报中得到了什么答案？
2. 当前变化是改善、恶化还是未确认趋势？
3. 比较是否严格使用可比期间和相同会计口径？
4. 报告变化中有多少来自真实经营，又有多少来自季节性、汇率、并购、会计重分类或一次性项目？
5. 用户能否在年糕Web中直观看到公司从历次报告到当前披露的判断、估值和动作演变？

## 2. 核心原则

- **同期优先**：H1只与上年H1比较，Q1只与上年Q1比较，Q3累计只与上年Q3累计比较，FY只与上年FY比较。
- **年报是锚、中报是脉冲**：最近年报保留长期商业质量和估值锚；中报用于更新信号，不把半年度流量直接替代全年常态盈利。
- **不可比就停止**：期间长度、合并范围、会计政策、币种或重述状态不清楚时输出`INCOMPARABLE`，禁止机械计算变化率。
- **逐题结算**：新披露必须回到冻结的`question_id`、竞争解释和区分信号，不得只生成自由文本“变化摘要”。
- **干扰必须可复核**：一次性、会计、季节性等不能只是标签；重要变化必须提供证据和可加总变化桥，未解释部分显式保留。
- **一次观察不是趋势**：单期变化只称观察或信号；结构性趋势需要足够的可比观察或后续披露确认。
- **单一真源**：Turtle追加式监控账本是审计真源；年糕SQLite与Web只是可丢弃、可重建的读模型，不得反向改写论点、概率、估值或动作。
- **历史回放不冒充前瞻成绩**：历史资料可验证管线，但只有真实发布时间后到达的新披露才能进入前瞻校准。

## 3. 目标数据流

```text
Turtle不可变发布快照
  ├─ 决定性问题、竞争解释、区分信号
  ├─ 事实、阈值、概率、估值与动作
  └─ 数据截止日、发布日期、来源指纹
                 ↓
新官方披露 → 可比期间解析 → 同期事实配对 → 干扰因素变化桥
                 ↓
问题逐题结算 → thesis/估值/动作影响候选 → 人工复核边界
                 ↓
追加式监控事件与纵向快照（唯一真源）
                 ↓
年糕只读投影 → API → 股票详情时间轴、趋势图、问题状态与变化桥
```

## 4. 工作包

### 4.1 可比期间身份与硬门

为财务事实补充或派生以下身份：

- `period_type`: `Q1/H1/Q3/FY/POINT_IN_TIME`；
- `period_start`、`period_end`、`duration_months`；
- `comparative_period_start`、`comparative_period_end`；
- `flow_or_stock`: 流量或时点；
- `restatement_status`与被重述的原始观察；
- `scope_id`: 合并范围身份；
- `accounting_basis_id`、`currency_basis_id`；
- `source_observation_id`。

比较配对器必须输出`COMPARABLE / ADJUSTED_COMPARABLE / INCOMPARABLE / MISSING_COMPARATOR`。流量指标禁止FY与H1直接比较；资产负债表时点可以跨节点展示，但必须明确间隔和不得称同比流量变化。

### 4.2 决定性问题监控合同

发布快照新增不可变`question_monitoring_contracts`，每项至少包含：

- `question_id`、原问题、基本解释和最强竞争解释；
- 可区分的信号及信号方向；
- 预期披露节点和最晚复核时间；
- 当时结论、置信度、概率集合；
- 对估值模型、估值区间、仓位和动作的传导；
- 支持“仍未知”的缺失证据条件。

新披露逐题生成`question_resolution`事件，状态限定为：

- `SUPPORTS_BASE_EXPLANATION`；
- `SUPPORTS_COMPETING_EXPLANATION`；
- `MIXED`；
- `INCONCLUSIVE`；
- `NOT_DISCLOSED`；
- `NOT_YET_DUE`。

每次结算必须绑定新`OBS:`/`CALC:`身份，说明概率、估值和动作影响。没有区分证据时不得提高置信度。

### 4.3 经营变化—干扰因素桥

对重要利润、现金流和分部指标建立变化桥：

```text
报告口径变化
= 可比经营变化（价格/销量/组合/效率）
+ 合并范围及并购处置
+ 汇率
+ 会计政策、重述及分类变化
+ 补贴、处置、减值等一次性项目
+ 季节性、工作日和基数效应
+ 其他已验证因素
+ 未解释残差
```

每一项保存金额或百分点、方向、来源和置信度。无法量化可用区间，但不得把未知残差归入“一次性”。桥接残差超过重要性阈值时，变化归因保持`INCONCLUSIVE`并阻断“结构性改善/恶化”结论。

### 4.4 趋势与状态迁移

分别维护：

- `observation`: 单期新事实；
- `signal`: 与旧问题方向一致的可比观察；
- `emerging_trend`: 至少两个连续可比信号但尚未跨完整披露周期；
- `confirmed_trend`: 至少三个可比观察，或中报信号被后续审计年报确认；
- `reversal`: 已确认趋势被后续可比证据反转。

状态迁移必须保留全部历史，不允许用新结论覆盖旧结论。趋势状态只作为研究辅助，不能自动触发交易。

### 4.5 年糕只读投影与Web

年糕增加可重建的研究监控读模型，建议最小表：

- `research_report_snapshot`：历次报告节点、数据截止日、发布日期、估值、动作及快照指纹；
- `research_question_history`：问题状态、证据、概率和判断变化；
- `research_metric_observation`：可比指标序列及口径身份；
- `research_change_bridge`：每个披露节点的变化桥；
- `research_monitoring_alert`：到期、缺失、不可比、触发和待复核任务。

这些表只能由Turtle账本投影重建，不作为事实或决策写入入口。同步必须幂等，并保存源事件ID、源文件指纹和投影版本。

股票详情页增加“研究跟踪”页签，至少展示：

1. **历史时间轴**：年报/中报/季报节点、当时价格、估值区间、动作、仓位与置信度；
2. **旧问题结算卡**：每个`question_id`从待确认到支持/反对/混合的演变及证据链接；
3. **同期趋势图**：H1序列、FY序列分开绘制，禁止把不同期间连成同一条趋势线；
4. **变化桥**：报告变化、可比经营变化、各类干扰和未解释残差；
5. **决策差异**：哪些新事实拟改变估值或动作、是否已人工批准；
6. **校准摘要**：预测结算数、样本量、Brier、触发器覆盖和研究错误率；样本不足醒目标注。

API建议：

- `GET /api/research/{ts_code}/timeline`；
- `GET /api/research/{ts_code}/questions`；
- `GET /api/research/{ts_code}/metrics?period_type=H1`；
- `GET /api/research/{ts_code}/change-bridges`；
- `GET /api/research/{ts_code}/calibration`。

Web不得重新计算同比、趋势分类、问题结算或动作，只展示API返回的已验证结果和明确的未知状态。

### 4.6 统一管线接入

- 正式发布时冻结问题监控合同。
- 新unified run先处理文档身份和可比期间，再生成事实差异。
- 比较不可用时生成可恢复任务，不进入论点结算。
- 问题结算和变化桥通过后，才生成decision diff candidate。
- Turtle监控周期完成后刷新年糕投影；投影失败不得破坏Turtle事件账本，也不得把研究周期误报成功。
- 无人值守扫描和外部通知仍保持独立授权，自动交易继续禁止。

## 5. 不可补偿质量门

- `INVALID`：FY与H1等不可比期间被计算为同比；历史结论被覆盖；来源事件或快照指纹不匹配；Web投影反向成为决策真源；未批准就改变动作。
- `INCOMPLETE`：缺少同期基数、重述或合并范围未知、重要变化桥残差过大、决定性问题到期但无可验证证据。
- `WARN`：只有一期信号、季节性调整不可获得、变化桥只能给区间、预测样本不足、投影延迟。

## 6. 验收标准

- [ ] 2025FY发布快照后摄取2026H1时，流量指标只与2025H1比较，2025FY仅作为年报锚。
- [ ] 至少一个旧`question_id`能被新中报结算，且证据、竞争解释、概率、估值和动作影响完整可追溯。
- [ ] 至少一个混合变化案例形成可加总变化桥；未知残差不会被自动归为一次性。
- [ ] 单期信号不会被误标为确认趋势。
- [ ] 历史回放与真实前瞻样本在UI和校准分母中明确分离。
- [ ] 年糕Web能展示同一公司的历次报告、同期指标、问题演变、变化桥和决策差异。
- [ ] 删除年糕投影后可从Turtle账本完整重建，结果指纹一致。
- [ ] A股、港股及至少一种高季节性或合并范围变化样本通过对抗测试。

## 7. 实施顺序

1. 可比期间身份、配对器和硬门。
2. 发布快照中的问题监控合同及逐题结算事件。
3. 干扰因素变化桥和趋势状态机。
4. 年糕数据库只读投影及同步器。
5. API和股票详情页“研究跟踪”视图。
6. 历史演练、真实前瞻样本和跨市场验收。

在1–3通过之前不先制作图表，避免把不可靠比较包装成精美但误导的趋势。
