# Phase 04：决策编译器

> 状态：COMPLETE ｜ 优先级：P0 ｜ 依赖：Phase 02、03 ｜ 最后更新：2026-08-02

## 1. 要解决的问题

同一份报告曾出现多套 `V_final`、折现率、λ、仓位和买入条件。仅靠事后正则检查不能根治自由写作造成的参数漂移。本阶段将账本设为唯一真源，关键结论由程序单向编译。

## 2. 目标与非目标

- 价格、估值、GG、II、λ、要求回报率、仓位和触发器只有一个canonical identity。
- Ch0、Ch9、Ch14及摘要动作区从结构化账本生成受保护区块。
- 不同情景/日期/口径必须带显式身份；旧版本只能以已废弃记录存在。
- 模型仍可写解释和反证，但不能覆盖编译后的参数和动作。

## 3. 核心接口

输入为 decision、valuation model、claim evidence、thesis test、insight ledgers。输出 `decision_ledger.json`、`decision_diff.json` 和关键章节编译片段。模板只引用ID，不复制自由数字。

### 3.1 编译顺序和真源

1. Agent先完成正文解释和全部结构化账本。
2. decision ledger从每个metric的active base/current身份中确定唯一canonical entry；其他情景、历史或模型口径仍可保留，但不得成为最终动作真源。
3. 组装前由程序编译Ch0、Ch9、Ch12、Ch13、Ch14受保护区块。
4. completion重新读取章节文件验证区块字节、来源指纹和区块外关键值。
5. 正式发布快照同时冻结编译清单和decision diff。

### 3.2 受保护标记

```text
<!-- TURTLE:DECISION_BLOCK:Ch14:BEGIN fingerprint=<sha256> -->
...仅由编译器生成...
<!-- TURTLE:DECISION_BLOCK:Ch14:END -->
```

区块内每个数值绑定具体`entry_id`。章节重写工具必须原样保留已有区块；删除、重复、修改或移动到错误章节均为`INVALID`。

### 3.3 区块外写作边界

- 允许解释机制、反证、模型适用性和为什么采取该动作。
- 允许显式情景/历史值，但必须有对应active decision ID。
- 不允许无ID的V_final、GG、II、λ、r*、安全边际、仓位或买卖触发值。
- 敏感性数字属于valuation/thesis账本时引用相应模型或阈值ID；不得伪装成第二套最终决策。

### 3.4 修订与迁移

首次生成的decision diff为`INITIALIZED/NOT_REQUIRED`。既有账本发生动作相关变化时diff先为`PENDING`，必须附变更原因、证据ID和批准身份后才能重新编译。冻结账本仍拒绝局部静默修改。

历史迁移只机械处理明确的关键参数行：canonical值补ID，冲突旧值移出决策区并记录迁移报告；不能从旧报告猜测哪个值正确。

## 4. 实施工作包

1. 统一关键指标和动作身份，定义版本、情景和废弃语义。
2. 编写账本一致性验证器和迁移器。
3. 为Ch0/Ch9/Ch14建立确定性编译模板与受保护标记。
4. 报告装配时拒绝修改受保护区块或出现游离关键值。
5. 每次发布生成decision diff，解释值变化的证据和批准状态。
6. 对历史多版本报告做对抗回放。

## 5. 质量门

- `INVALID`：未解释的跨章冲突；动作不满足自身回报/安全边际条件；自由文本出现无身份关键值；旧值复活。
- `INCOMPLETE`：账本缺少形成动作所需输入或修订理由。
- `WARN`：仅解释文本不一致且不改变决策含义。

## 6. 完成标准

- [x] 关键指标和动作均来自唯一账本。
- [x] 编译区块重复生成字节稳定。
- [x] 参数变化自动生成可审阅decision diff。
- [x] 多版本格力用例被硬门拦截，已知旧口径可机械迁移，未知值拒绝猜测。
- [x] 自动管线和历史兼容测试通过。

## 7. 验收结果

- 新增`decision_compiler.py`、编译清单/策略schema及Phase 26对抗测试。
- Ch0、Ch9、Ch12、Ch13、Ch14在组装前由冻结账本生成；写章工具保留编译器区块，删除、重复、篡改、来源变更均阻断。
- 区块外canonical值必须绑定decision ID；估值敏感性和竞争情景允许绑定已存在的valuation/thesis/threshold/claim身份，不能用虚构ID绕过。
- 动作变化diff必须同时匹配当前账本指纹并带批准身份、理由和证据ID；Buy/Avoid与安全边际、仓位矛盾时不写入任何区块。
- 历史迁移只绑定唯一匹配值；deprecated值显式标记且不参与最终动作；未知或歧义值进入迁移报告。
- 定向全回归：`300 passed`。全仓无参数运行仍受可选`tushare`依赖与嵌套旧仓库测试包重名影响，与本阶段无关。
- 真实影子回放：格力旧稿中的多版本参数被游离值门捕获；金融街物业Phase K副本成功编译五章，并将观察仓范围、未绑定r*推导和退出条件三处语义缺口保持为`INVALID`，未改写原输出。

## 8. 剩余限制

账本保证一致性，不保证概率准确。旧报告没有完整结构化账本时保持`SKIP`，只通过显式迁移进入新门；后验评价由Phase 05、06完成。
