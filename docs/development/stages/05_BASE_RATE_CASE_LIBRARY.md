# Phase 05：基准率案例库

> 状态：COMPLETE ｜ 优先级：P1 ｜ 依赖：Phase 01、02 ｜ 完成日期：2026-08-02

## 1. 要解决的问题

报告中的主观概率和类比常缺少基准率，也容易在知道结果后重写当时判断。需要保存“当时可见信息—预测—结果”的不可变案例，逐步校准研究判断。

## 2. 目标与非目标

- 建立as-of-time案例快照，严禁使用当时不可见信息。
- 记录概率类型：频率、历史基准率、主观判断或情景工作假设。
- 案例按机制和原型检索，不按公司名称做表面类比。
- 不用短期股价单独判断分析好坏，不把相关性包装为因果。

## 3. 核心接口

使用版本化 `case_library.jsonl` 或等价存储，包含 `case_id`、as-of日期、可见证据指纹、问题/竞争解释、预测、概率来源、观察窗口、结果、评分状态和泄漏审计。原始发布快照不可修改，结果以追加事件连接。

### 3.1 记录分层

- `CANDIDATE`：从现有报告或决定性问题计划机械提取，但披露日期、当时概率或结果尚未审完；永远不能进入基准率分母。
- `REVIEWABLE`：as-of事实、预测、概率类型和来源指纹完整，但观察窗口未结束。
- `RESOLVED`：结果以独立追加事件记录，原案例字节不变。
- `ELIGIBLE`：结果已解决且通过独立资格复核，才可参与跨公司基准率。
- `EXCLUDED`：存在未来信息泄漏、不可比、选择偏差或来源不可复核；保留记录但不参与统计。

案例状态由不可变case记录和追加事件共同推导，禁止原地把候选改成成功案例。

### 3.2 防泄漏契约

1. `information_cutoff`是当时可见信息的唯一时间边界。
2. 每项证据保存`disclosed_at`、`data_as_of`、文件哈希和`source_group_id`；披露日晚于cutoff即`INVALID`。
3. prediction只保存当时预测，不得含outcome、resolved或事后解释字段。
4. outcome事件的观察及来源必须晚于cutoff，且不得反写case。
5. 同一原始来源的转载只算一个source group。
6. 130家公司估值模型只允许作为机制/模型结构参考，`company_fact_eligible=false`，不能充当结果样本或参数来源。

### 3.3 检索与统计边界

- 检索必须先匹配`mechanism_key`，再按公司原型、变量和观察窗口排序；禁止按公司名称表面类比。
- 只有`ELIGIBLE`且已解决案例进入经验频率；少于5个可比案例时展示计数和缺口，不输出base-rate概率。
- 每个基准率引用返回case ID、case fingerprint和结果事件ID，可回到当时证据。
- 基准率只是先验；公司特定VERIFIED证据可以更新它，但不能被它替代。

### 3.4 与自动管线的连接

统一运行在决定性问题生成时写入`base_rate_context.json`，将机制匹配结果冻结到本次run。后续case library新增记录不会静默改变已生成报告。`base_rate`类型概率必须引用本次context中的eligible case ID；否则发布门失败。没有合格样本时允许继续使用明确标注的主观概率或情景权重，并产生样本不足WARN。

## 4. 实施工作包

1. 定义案例、预测和结果schema及防泄漏规则。
2. 将现有高质量报告提取为候选案例，人工/程序核对当时信息。
3. 建立按商业原型、机制、变量和时间窗口的检索。
4. 为Phase 02提供基准率证据，但禁止自动替代公司特定证据。
5. 设计概率校准和案例质量报告。

## 5. 质量门

- `INVALID`：未来信息泄漏；结果反向覆盖原始预测；概率没有类型或时间戳。
- `INCOMPLETE`：观察窗口未结束或结果不可验证。
- `WARN`：样本过少、选择偏差大或案例可比性弱。

## 6. 完成标准

- [x] 案例与结果追加式存储，发布快照不可变。
- [x] 泄漏、重复来源和不可比案例有自动检查。
- [x] 至少覆盖三个原型并形成首批可审计样本。
- [x] 基准率引用可回到案例和原始证据。
- [x] 对概率只做有样本量说明的校准展示。

## 7. 实施结果

- `scripts/base_rate_case_library.py`提供案例、结果事件、资格复核、排除、机制检索、上下文冻结、质量审计和真实输出候选提取；存储位于`output/.base_rate_library/`，case与event均为追加式JSONL。
- `base_rate_context.json`在决定性问题生成时自动产生；`base_rate_policy.json`把新unified run纳入完成门。上下文、案例和结果事件指纹会进入发布快照。
- `base_rate`概率必须引用本次上下文中的至少5个同机制`ELIGIBLE CASE:`；样本不足只能使用明确标注的主观概率或情景权重。
- 130家公司估值模型索引被运行时规则明确拒绝为历史案例证据，只保留机制/模型结构参考角色。
- 首批真实候选来自格力电器、分众传媒和中海物业：9个case、3个原型、4类机制。全部保留为`CANDIDATE`，没有事后补写概率或结果。
- 阶段与既有主干回归：`314 passed`。

## 8. 剩余限制

当前`ELIGIBLE`样本数为0，因此系统不会展示经验基准率。候选案例仍需核验各来源披露日期、冻结当时概率，并等待观察窗口后的独立结果事件和资格复核。长期统计效力需要时间积累；Phase 06负责自动观察、到期回填和校准。
