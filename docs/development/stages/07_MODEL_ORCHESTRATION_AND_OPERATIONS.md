# Phase 07：模型编排与运行治理

> 状态：COMPLETE ｜ 优先级：P1 ｜ 依赖：贯穿各阶段，最终收口 ｜ 最后更新：2026-08-03

## 1. 要解决的问题

多轮开发后，模型调用、缓存、密钥、运行产物和失败恢复分散。降低成本若没有质量边界，会重演上下文不足和研究退化；缺少运行治理也会让真实失败被静默忽略。

## 2. 目标与非目标

- 经用户明确授权，现有本地文件继续作为密钥真源且不改变读取方式；这些文件必须保持未跟踪/被忽略，密钥不得进入日志、缓存、诊断、manifest或正式产物。未来迁移到系统密钥库是可选项，不是本阶段阻断项。
- 按任务风险进行模型分级，证据、推理和决策关键步骤不得自动降质。
- 基于输入指纹复用确定性产物，模型输出缓存必须带版本和过期策略。
- 每次运行产生统一manifest、成本、时延、重试、截断和失败码。
- 清理与保留策略自动化，但正式快照和可复核证据不可被无声删除。

## 3. 核心接口

`run_manifest.json` 记录 run ID、代码/配置版本、输入指纹、模型和prompt版本、步骤状态、token/成本、缓存命中、重试、产物和发布结果。配置分为质量不可变项、运行预算项和本地秘密项。

## 4. 实施工作包

1. 盘点本地密钥文件并保持现有读取路径，提供版本控制隔离、启动自检和脱敏日志；不读取或展示密钥值。
2. 定义任务级模型路由：抽取、验证、深推理、挑战者和最终综合。
3. 给上下文与模型调用增加内容寻址缓存、TTL和失效条件。
4. 统一超时、重试、限流、上下文截断和错误传播。
5. 建立成本/时延预算；预算不足时暂停或降范围，不静默降低关键推理质量。
6. 自动执行仓库与运行产物保留策略，先预览后删除。
7. 更新运行手册和故障恢复演练。

## 5. 质量门

- `INVALID`：明文密钥进入已跟踪代码、日志或运行产物（用户批准且被忽略的本地密钥文件除外）；关键步骤因预算静默换低能力模型；失败被标记成功；缓存跨公司或期间污染。
- `INCOMPLETE`：预算耗尽、模型不可用或关键步骤未完成。
- `WARN`：非关键补充研究被限流、缓存接近过期或成本异常。

## 7. 最终实现

- `config/runtime_governance.v1.json` 是任务能力下限、重试、超时、限流、预算、缓存、价格登记和保留策略的版本化真源。
- `scripts/runtime_governance.py` 提供任务路由、预算裁决、内容寻址缓存、原子manifest、脱敏、密钥边界审计、保留预览/可恢复移动、manifest验证和恢复建议。
- `LlmClient` 只保留一层统一重试，按错误类型决定是否重试；关键任务截断被拒绝，带工具副作用的响应不缓存。
- `run.py` 自动创建 `run_manifests/{run_id}.json` 和最新 `run_manifest.json`，对准备阶段、模型调用、token、时延、缓存、产物与发布结果进行闭环记录。
- 用户批准的 `analyze.sh` / `.env` 保持原位且读取方式不变；两者已进入 `.gitignore`。实际边界审计为 `PASS`，未发现运行产物泄漏。
- 实际保留预览保护271个证据/发布文件，无到期候选，因此未移动文件；执行路径必须按计划指纹确认，并只移入可恢复垃圾区。

## 8. 验证结果

- 阶段对抗测试：`12 passed`，覆盖模型降级、预算耗尽、超时重试、关键截断、跨公司/跨期缓存、缓存篡改、密钥泄漏、manifest伪成功、清理误伤和统一主流程干跑。
- 主干阶段回归：`338 passed`，此前基线326项全部保留。
- 真实 DeepSeek 极小烟测：响应成功，manifest `PASS`，token与缓存事件可见，密钥未进入manifest，未触碰公司报告。
- 格力、金融街物业、中海物业和分众传媒四个真实目录均可生成六类核心输入指纹，覆盖A股/港股、成熟制造/物业/轻资产原型。

## 9. 已接受限制

- 模型价格具有时效性，默认不硬编码金额；未登记价格时记录token/时延并明确警告，不能伪造成本精度。
- 本阶段只提供安全恢复入口，不引入无人值守自动发布或自动交易。
- 本地密钥文件是用户明确选择，不视为本阶段缺陷；若未来迁移系统密钥库，必须保持现有启动方式的向后兼容。

## 10. 后续维护

模型能力和价格会变化，路由必须由真实研究质量定期校准，不固化为永久供应商选择。
