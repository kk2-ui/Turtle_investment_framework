# 企业经营系统图

状态：`DISCOVERY / FROZEN_FOR_REVIEW / OUTCOME_REVEALED / RECOMPOSED / CLOSED`

用途：在研究任何单一 decision episode 前，把企业作为一个相互作用的经营系统来理解。它不是公司概览、行业资料堆叠、估值模型或管理层评分表；它只保留能够改变客户价值、行业租金、现金转换或资本回收的系统关系。

一张[企业经营判断卡](research_enterprise_judgment_card.md)只验证本图中一条关键箭头，**不能替代本图来宣布公司结论**。本图的上位目标是让 agent 先像经营者一样理解“整个系统如何运转/失灵”，再像行业专家和所有者一样判断某个决策会改变哪一处。

## 2. 四个必须同时存在的系统面

先用同一 cutoff 的事实填写。没有一手事实的格写 `UNKNOWN`；不要用管理层愿景、行业排名、价格或后来结果补全。

| 系统面 | 当前可观察事实 | 形成经济性的关键关系 | 仍未知/最危险的替代解释 |
|---|---|---|---|
| `CUSTOMER_AND_ARENA`：客户问题、替代、需求质量、行业供给、竞争/渠道/供应商/政策 |  | 客户为什么选择/不选择；谁能截取租金；外部状态如何约束公司 |  |
| `VALUE_AND_CAPTURE`：产品/服务、价格/数量/组合、服务承诺、合同/收费与毛利 |  | 价值如何被交付、被支付并留下贡献，而非只留下收入 |  |
| `ACTIVITY_AND_ORGANIZATION`：研发、采购/制造、产能、渠道、服务、组织权责与激励 |  | 一组活动怎样共同支撑或拖累价值交付；实际决策权在哪个责任单元 |  |
| `CASH_AND_CAPITAL`：应收、存货、应付、资本开支、债务/外部融资、再投资与资产负债表 |  | 销售和利润如何（或为何不能）穿过营运资本成为可再投入现金 |  |

上表要求完整的**经济连接**，不要求把公司所有部门和指标写进来。一个变量若不会改变中心问题或某条关键连接，应当删去。

## 3. 企业的活动系统与反馈回路

### 3.1 价值创造—捕获的主链

```text
客户任务/替代与行业状态
  → 产品/服务承诺与价格实现
  → 研发、制造、渠道、服务和组织协同
  → 单位贡献、订单质量与竞争反应
  → 应收/存货/应付、资本支出与融资
  → 可再投入能力、资产负债表韧性与下一次资源选择
```

| 客户/行业 → 产品价格/数量/组合 |  |  |  |  |
| 产品承诺 → 活动/组织要求 |  |  |  |  |
| 活动系统 → 单位经济/交付质量 |  |  |  |  |
| 单位经济/竞争反应 → 营运资本 |  |  |  |  |
| 营运资本/资本开支 → 可再投入与韧性 |  |  |  |  |
| 结果反馈 → 下一次资源选择 |  |  |  |  |

### 3.2 选出不超过三条真正的反馈回路

回路不是“增长很好/竞争激烈”的句子，必须写出因果方向、时滞和可能的反转。常见形态包括：

```text
客户采用 → 规模/学习 → 成本或服务能力 → 更强客户采用
增长/交付 → 应收与存货占用 → 融资/资本约束 → 产品、渠道或产能选择
价格/渠道动作 → 竞争者回应 → 行业租金/服务负担 → 下一轮价格与渠道动作
产品/服务现场反馈 → 管理者修正资源选择 → 下一次交付质量/客户选择
```

| 回路 ID | 完整因果环、时滞与存量（产能、渠道库存、安装基数、应收等） | 自我强化的条件 | 失速/反转的条件 | 该回路最关键的可观察信号 |
|---|---|---|---|---|
|  |  |  |  |  |

不要为了“系统性”把所有关系画成回路。无法给出时滞、存量或可观察信号的关系仍是背景，不能成为公司结论。

## 5. 管理层决策在系统中的位置

不是所有动作都叫战略。对每个 material 决策，先说明它服务于哪个诊断、哪些活动必须协调、成本/机会成本和反馈如何回到下一轮选择。

| 管理决策/不作为 | 试图解除的系统瓶颈 | 必须共同变化的活动/责任单元 | 对客户、竞争和现金的预期副作用 | 最早停止/修正条件 | 对应 decision episode card |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

如果一个被称为“战略”的动作不能在此表指出系统瓶颈、协调活动和可观察副作用，它只能是 `ACTION_OBSERVED`，不是战略判断。

| card / observation | 更新的箭头或回路 | `SUPPORTS / WEAKENS / MIXED / NOT_DIAGNOSTIC / UNKNOWN` | 因此改变了什么系统判断 | 仍未覆盖的 material link | 下一张卡应验证什么 |
|---|---|---|---|---|---|
|  |  |  |  |  |  |

一个系统结论至少要说明：它由哪些已结算卡支持、哪些 material link 仍为 `UNKNOWN`，以及是否因此只能得出 `PARTIAL_SYSTEM_VIEW`。不能把数张同方向卡拼成“管理层总体优秀”或“公司很强”。

## 8. 本图的训练验收

本图不是因为写满而通过。每次使用时只检查四件可变更研究行为的事：

1. **整体性**：H-A/H-B 是否都覆盖客户、活动/组织、竞争与现金/资本，而不是只解释一个 KPI；
2. **耦合性**：是否识别出至少一条会跨系统改变结论的箭头或回路；
3. **节制性**：单卡是否被明确限制为验证一条箭头，且 material `UNKNOWN` 没有被补写；
4. **反馈性**：结算后是否真的改变 map 中下一条要验证的连接，而不是追加公司史。

若任一项未满足，正确状态是 `SYSTEM_UNRESOLVED` 或 `PARTIAL_SYSTEM_VIEW`，不是把单机制卡升级成完整报告。

## 9. 方法边界

本图借用四个互补的研究/管理视角：Porter 的活动匹配强调竞争优势来自一组相互强化的活动；Teece 将商业模式视为价值创造、交付和捕获的架构；Sterman 的系统动力学强调存量、流量、时滞和反馈；Rumelt 的策略 kernel 要求诊断、指导方针和协调行动。这些来源只提供组织企业问题的语言：

- [Porter, *What Is Strategy?* (1996)](https://hbr.org/1996/11/what-is-strategy)；
- [Teece, *Business Models, Business Strategy and Innovation* (2010)](https://doi.org/10.1016/j.lrp.2009.07.003)；
- [Sterman, *Business Dynamics* (2000)](https://web.mit.edu/jsterman/www/pub.html)；
- [Rumelt, *Good Strategy/Bad Strategy* (2011)](https://www.penguinrandomhouse.com/books/208668/good-strategy-bad-strategy-by-richard-rumelt/9780307886231/)。

它们不证明任何公司、行业、管理层或 Turtle 已具备系统判断能力；只有冻结前的公司事实、后续可结算观察和跨对象复验才能做到这一点。
